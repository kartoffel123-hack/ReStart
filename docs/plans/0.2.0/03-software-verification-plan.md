# Software Verification Plan

**ReStart 0.2.0 · CT demo acceptance and helicopter non-regression**

[Design and five candidate pieces](01-software-design-plan.md) · [Engineering owners and tickets](02-software-design-implementation-plan.md) · [Original V01–V10 requirements](../0.1.0/03-software-verification-plan.md)

## What counts as a pass

| Lane | Required evidence | Decision |
|---|---|---|
| Existing helicopter pilot | Same 70 selectable IDs, all 13 packaged single targets and joint route replayable, same physical instructions, metrics, procedure fingerprints and observable UI behaviours. Record the baseline from the pinned generation before refactoring. | Any lost working repair or view blocks the shared-runtime change. Do not silently regenerate expected results. |
| Helicopter full release | Existing independent 70-target verifier and three uncoached trials retain their original meaning. Compare per-target results to baseline when changing common code. | An existing shortfall remains reported. An improved CT count cannot make this lane green or excuse a new helicopter failure. |
| CT demo | Entire reconciled assembly present in Fusion, exported STEP and web inventory. All advertised manuals reviewed, independently replayed and browser-tested. **Minimum one** of those exact manuals also passes an uncoached trial; aim for five selectable demo repairs. | An incomplete CAD assembly or zero working manuals cannot replace the default. Label physical evidence per route. Never present one or five successes as 566 verified repairs. |

## Mechanic Manual: production browser protocol (CT-V05)

1. **Identify.** Starting at `/`, use both search/keyboard and a real canvas raycast to reach the *same* occurrence. Dragging to orbit must not pick. Select an adjacent same-type piece and verify that location, inset, highlighted mesh and graph selection change together. Select a buried part from the list. An unsupported selection explains why no manual starts; it cannot start the previous selection's repair.
2. **Follow one action.** Start the lead route and observe remove → replace → restore → check. During access, compare affected IDs, direction, tool, stop, camera and parked neighbours with the reviewed trace. Verify overview/inset visibility for each phase and the replacement's independent close-up. Pause, replay, orbit, reset and inspect history; none commits a step. Reconfirming an old step ID has no effect. If a route has no blockers, restoration still seats the spare.
3. **Resume.** Reload mid-repair. Require the mechanic to reconcile kit state before resuming the matching target, revision, fingerprint and confirmed index. Change the fingerprint and reject resume. Exercise old helicopter checkpoints after CT becomes the default: no CT step advances and the compatible helicopter recovery remains available.
4. **Finish or fail.** Select failed fit check; completion stays disabled until inspection and successful recheck. Confirm success; compare the exported target, spare, disturbed IDs/count, retained units, timing coverage/basis, procedure fingerprint and evidence status with independent replay. Missing estimates are unknown; untried routes cannot be marked physically verified.
5. **See and operate it.** At 1280 × 800 and 390 × 844 check text, direction arrow, stop pose and next-action control without horizontal scroll. For the first route have a teammate identify the exact brick and direction from the page. Exercise keyboard focus, reduced motion and unavailable WebGL with text guidance; simulate asset failure and retry. Record actual production URL/browser matrix (clean Windows Edge and macOS Safari); use Playwright as the repeatable preflight.
6. **Keep the helicopter tests meaningful.** Pin the original scenario's dataset instead of replacing its assertions with CT strings. Retain `tests/e2e/light-stud.spec.ts` (drag vs pick, four phases, fit-check failure/retry, completion and overview) plus the buried-pin, cross-block, joint-repair, graph-layout, picker-layout and review-session specs. Add a CT counterpart using its source witness, real canvas and exact CT result. Exercise the dev gallery separately against the same exported presentation components.

## Bench record (CT-V08, manual; outside CI)

Stage the assembled toy, agreed tools and matching spare. Freeze source/STEP/graph revision, target, procedure fingerprint and expected disturbed IDs. Record the undisturbed reference condition (e.g. curve orientation or door swing). A non-author selects the indicated occurrence and uses only the webpage. An observer notes actual IDs moved, tool/side, stopping and seating landmarks, phase times, deviations and final check. Record roles without personal data. A spare stand-in may establish a rehearsal; disclose it and do not count it as an actual spare replacement. If the kit is unavailable, publish only a model/browser result to staging.

On a deviation, save the failed step and evidence, fix the graph, geometry or cue, regenerate and replay all offered manuals, and repeat the trial on the new procedure. A successful old fingerprint is historical, not transferable to a changed action. A timing-label correction alone must not erase a still-identical procedure's evidence after fresh replay.

## Release decision and rollback

1. Pin Node 24.22.3 and use `npm ci`. With the original package record `npm run typecheck`, `npm test`, `npm run build`, `npm run test:e2e` and the helicopter import/compile/verify batch. Retain the per-target report, including unresolved targets; do not promote a failing release dataset. Capture package digests and representative screenshots.
2. Add explicit dataset selection to the build-side commands. Proposed CT sequence: `npm run model:import -- --dataset 4000041` (from the pinned CAD export), `npm run model:compile -- --dataset 4000041`, then `npm run model:verify -- --dataset 4000041 --profile demo`. The demo verifier exits nonzero for an unreconciled occurrence, zero manuals, a declared demo target without a valid manual, or any failed route. Output a row for every inventory ID, including unavailable reason, and separate physical evidence status. Existing helicopter full-release defaults remain strict.
3. On the candidate build rerun typecheck, complete Vitest, both dataset checks and both production E2E contexts. Review CAD round-trip, browser and bench records against the exact generation. Prepare a release record with source hashes, converter/library versions, Fusion revision, resolved inventory count, supported target IDs, route fingerprints, replay results, physical outcomes, device timings and any rejected candidates. Never silently shrink the declared demo list to turn verification green.
4. Switch only the shared default descriptor after sign-off. On the hosted URL cold-open the picker, complete the CT lead repair, hard-refresh graph/review/DoF, and check package revision in the export. An existing helicopter tab must remain bound to its generation or explicitly request a restart. No manual, source CAD or model service should be fetched from the sibling dataset by accident.
5. Rehearse rollback to the captured helicopter selector/build with its immutable assets still served. In a clean browser complete the light-stud route and open review; prove a stored CT checkpoint does not advance it. Restore CT and repeat the CT smoke test. Keep the helicopter default if any gate fails. Progress screenshots document work; release sign-off is the matrix above.
