## CT-02–04: Studio → Fusion → STEP → browser

For the scoped export, use `tools.ct.fusion_assembly.assemble(staging_path, sample=False, demo=True)` in Fusion with the repository on its Python path. This creates a new design and writes `fusion-demo.step` and its native body-volume witness under `.tmp/ct/`. Reopen it with the CAD environment's `python -B -m tools.ct.check_step --demo --export-meshes`. The checker reads the pinned archive, compares placement and hierarchy, and writes separate demo meshes and a demo fidelity report; the full assembly remains the reference for out-of-scope blockers.

1. Index the pinned archive in memory. Parse the root and MPD sections; retain colour inheritance, local transformation matrix, parent and occurrence locator. Build the drawable dependency tree separately from the serviceable inventory. Join v2 placement records by reference, transform and colour; verify uniqueness before using a Studio identifier. Handle nested, repeated, reflected and non-rigid source transforms explicitly. Report cycles, unresolved aliases, custom overrides and conflicting geometry with the affected paths. Hash the exact resolved library files and version the decisions; do not require a developer's absolute Studio path at runtime.
2. Measure independent source witnesses: distance between known studs (20 LDU = 8 mm), a repeated pair with different origins, and a rotated asymmetric piece (printed tile or door). Record source-up, assembly axes and local landmarks. Use 0.4 mm/LDU; account for Fusion API internal centimetres, domain millimetres and glTF metres at their respective boundaries. Convert a frame once, including basis/handedness, then compose child placements. Check reflection/winding or bake variant geometry when a rigid Fusion transform cannot express the source shape.
3. Inspect the existing Fusion `CT` document and sibling helicopter structure read-only. Work in a new revision or staging design under the confirmed destination. Keep the existing document available until the candidate is verified. Select only the Fusion component groups `MRI` and `Mid section` for the demo assembly; explicitly exclude the flexible string/rope occurrence(s), even if nested in either group. Record excluded groups and occurrence IDs and verify none leaks into STEP/GLB. For each distinct in-scope definition prefer a matching solid with verified geometry, or construct a solid from measured part features. Test mesh stitching/conversion on the small sample: LDraw visual faces can be open or overlapping, and a faceted solid may lack analytic stud or bore faces. Rebuild failed bodies, document approximations, and reject any that change a reviewed grip, clearance or seating surface. Treat decorative print as appearance, with a retained orientation witness. Check terms/attribution for geometry distributed with the demo.
4. Insert reusable in-scope components at their source transforms, preserve the named `MRI` and `Mid section` hierarchy, and retain source occurrence locators in a sidecar crosswalk. Do not copy helicopter stage numbers or infer blockers from build order. Save Fusion design/version and export a scoped **assembly STEP**, recording group allowlist, exclusions, format, options, units and digest outside immutable `assets/`. Reopen it with an independent STEP reader and test the actual exporter dialect before reusing the AP203-specific importer. Recover identity from hierarchy plus definition, pose and geometry; reject a flattened assembly or a guessed nearest match. A reordered export may change STEP entity numbers without changing which physical piece was selected.
5. Reuse build-side tessellation and GLB inspection. Emit one pickable logical occurrence per approved in-scope physical row; group submeshes and share geometry buffers where possible. Record independent geometry, pick and colour/orientation witnesses, plus an exact exclusion check against Base, Back room, Control room, Decoration, Minifigs and every string/rope occurrence. Keep the approved STEP and conversion provenance available to builders; a static-site build uses the checked compiled generation, not a live Fusion session. Report scoped assembly extents, triangle count, package size and first-frame/first-step times on the demo machine before increasing detail.

## CT-05/07: repair authoring and delivery

**CT-05 measurement:** [Intact turntable access and restoration](../../../data/review/4000041/turntable-access.md) records the roof-open lift, bench transfer and reverse stroke. Both the two-piece unit and the variant carrying twelve pins collide on exit and reseating. No gear operation is eligible for the scoped catalog from this result.

The [L110/L331 fixture trials](../../../data/review/4000041/turntable-blocker-trials.md) test individual and supported parking, reverse the motions and repeat the turntable sweep. Thin-jaw tile access is a bench candidate; the round-brick bridge remains obstructed by the side wall. Even the most permissive tested tray state leaves `L237` in the toothed top's path.

For the MRI gear first, identify the exact occurrence and spare, then write down the intended individual release, approach side, gear/axle dependencies, permitted mating contacts, support, tool envelope, stop, orientation/indexing and return **before** running the planner. Check the complete in-scope installed neighbourhood. Where extraction needs a blocker, record both its parked state and validated return. Use independent sweep checks and link the public graph to reviewed evidence. Compare the measured route difficulty with the current gantry-support baseline; do not assert “harder” from visual appearance alone. The function check names an observable scanner behavior, such as restored gear engagement. Pin target, ordered moves, physical instructions and check to a procedure fingerprint. Publish only browser-tested, replayable manuals; retain rejected attempts in a worklist. An out-of-scope blocker cannot be silently moved as a demo operation: either include its group through an explicit scope decision or reject the candidate.

Build in a separate `public/models/4000041/` namespace with immutable generations; keep `30465` and previous assets available. Validate both packages before atomically changing one default selector shared by all routes. Do not repoint the helicopter channel at CT. Budget for one complete repair before spending time on the fifth. The final [verification sequence](03-software-verification-plan.md#release-decision-and-rollback) determines whether to switch or keep staging. Follow the repository's progress evidence convention at each implementation commit.
